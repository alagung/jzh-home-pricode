# 自动生成漫画故事项目计划

## 1. 项目概述

本项目旨在打造一个**自动生成漫画故事的视频创作系统**，专为儿童教育设计。系统能够根据用户设定的角色和故事内容，自动生成适合手机阅览的竖屏漫画图片序列（约 10 帧），合成为视频，自动添加配音，并上传至短视频平台。

### 1.1 项目背景
随着短视频平台的普及和儿童教育需求的提升，家长和教育者需要高质量、有教育意义的儿童内容。本项目通过 AI 技术自动化生成漫画故事视频，降低内容创作门槛，同时确保内容的教育价值和文化传承意义。

### 1.2 项目目标
- 为小学低年级和高年级学生提供分级定制的漫画故事内容
- 传承中国传统文化，同时引入世界文学名著
- 实现从故事输入到视频发布的完全自动化流程
- 支持多语言版本（中文、英文、阿拉伯文）

### 1.3 核心功能
1. **角色设定系统**：创作者提供简要描述，由 AI 生图系统生成多个卡通角色供选择，确定故事主角
2. **分级内容创作**：
   - **低年级段**（1-3 年级）：以讲故事为主，内容源自中国传统文化小故事，涵盖中国历史、地方风俗等，适合亲子共读或孩子自主阅读/收听
   - **高年级段**（4-6 年级）：文学作品初步阅读，内容精炼简化，以中国故事为开端，逐步引入世界范围文学名著
3. **多语言支持**：所有内容提供中文、英文、阿拉伯文译本
4. **自动化视频生成**：生成竖屏尺寸图片序列→合成视频→自动配音→上传短视频平台
5. **具体技术指标**：
   - 生成适合手机阅览的图片尺寸（如 1080x1920 像素）
   - 连续生成约 10 帧连贯的漫画故事图片
   - 将图片序列合成为视频
   - 自动添加配音（语音合成）
   - 自动上传至短视频平台（抖音、快手、TikTok 等）

## 2. 需求分析

### 2.1 功能需求

#### 2.1.1 角色设定模块
- **角色描述输入**：创作者提供简要的文字描述（如性格、外貌特征、服装风格等）
- **AI 角色生成**：基于描述生成多个卡通角色候选图供选择
- **角色确认与存储**：用户选择确定主角后，保存角色特征用于后续连续帧生成
- **角色一致性保障**：确保同一角色在不同场景、不同帧中保持一致的外貌特征

#### 2.1.2 内容创作与管理模块
- **分级内容库**：
  - 低年级段：中国传统文化小故事（历史故事、地方风俗、民间传说等）
  - 高年级段：中国文学作品及世界文学名著的精简版
- **内容筛选机制**：根据目标年龄段自动筛选适宜的故事内容
- **多语言翻译**：支持中文、英文、阿拉伯文三种语言的剧本和配音
- **剧本适配**：将故事内容适配为约 10 帧的漫画分镜剧本

#### 2.1.3 图像生成模块
- 基于 AI 模型生成高质量漫画风格图片，支持竖屏尺寸（1080x1920）
- 连续生成约 10 帧连贯的漫画故事图片
- 确保生成的图片在角色、场景、风格上保持一致性

#### 2.1.4 视频与音频合成模块
- **视频合成**：将图片序列按顺序合成为视频文件，支持设置帧率和转场效果
- **语音合成（TTS）**：根据剧本自动生成配音，支持多语言和多音色，适合儿童收听
- **音频合成**：将配音与视频画面同步，可添加背景音乐和音效

#### 2.1.5 发布与运营模块
- **自动上传**：对接主流短视频平台 API（抖音、快手、TikTok 等），实现自动发布
- **内容管理**：剧本管理、素材库、角色库、发布记录管理
- **数据分析**：播放量、互动数据跟踪（可选）

### 2.2 非功能需求
- **性能要求**：单条视频生成时间控制在 5 分钟以内
- **稳定性**：系统可用性达到 99%，支持批量任务队列
- **安全性**：用户数据加密存储，API 密钥安全管理；儿童内容安全审核机制
- **扩展性**：支持新增短视频平台接入，支持新的 AI 模型替换
- **内容合规**：符合儿童内容保护规范，各语言版本符合当地文化习俗

## 3. 技术方案

### 3.1 技术栈

#### 3.1.1 角色与图像生成（API 化架构）

**核心设计理念：两步式 API 交互模式**

将生图功能完全 API 化，分为**提示词生成**和**图片生成**两个独立步骤，确保用户对创作过程的完全控制。

- **核心引擎**：**Flux.1-dev**
- **API 架构设计**：

  **第一步 - 智能提示词生成 API**
  - **输入**：用户一句话描述（如"一个穿着汉服的古代小女孩，拿着灯笼"）
  - **处理**：LLM 自动扩展为完整的专业提示词（包含风格、光影、构图、细节等）
  - **输出**：完整的英文提示词 + 中文翻译，等待用户确认或修改
  - **示例流程**：
    ```
    用户输入 → "一个勇敢的古代小将军"
    ↓
    LLM 处理 → "A brave ancient little general, wearing traditional Chinese armor, 
                holding a small sword, standing confidently, cartoon style, 
                vibrant colors, soft lighting, 3/4 view, detailed facial features"
    ↓
    用户确认/修改 → 发送最终提示词到第二步
    ```

  **第二步 - 图片生成 API**
  - **输入**：用户确认后的完整提示词 + 角色参考图（可选）+ 图片数量参数
  - **处理**：调用 Flux.1-dev 进行图像生成
  - **输出**：返回 1 张或多张候选图片（数量可配置，默认 4 张）
  - **支持场景**：
    - **角色生成**：无参考图，根据提示词生成多个角色候选
    - **故事画面生成**：提供角色参考图，保持角色一致性生成场景图
    - **道具/场景扩展**：在参考图基础上添加新元素

- **角色一致性方案**：
  - **参考图驱动（Image-to-Image）**：利用 Flux.1-dev 强大的原生特征保持能力，仅需**一张主角设定图**作为输入，即可在后续所有分镜生成中完美保持角色面部、发型、体型的一致性。
  - **无需训练**：摒弃传统的 LoRA 模型训练流程（通常需数小时），实现秒级推理响应。
  - **道具与场景扩展**：支持通过提示词或额外参考图，灵活为角色添加特定道具（如历史兵器、传统服饰）、切换不同场景（如古代街道、山水背景），同时不破坏角色特征。

- **辅助控制**：
  - **构图与姿态**：结合 ControlNet 或 Flux 内置的姿态控制，确保分镜连贯性。
  - **风格化**：预设漫画/卡通风格 Prompt 模板，确保输出符合儿童审美。

- **API 接口定义**：
  ```python
  # 步骤 1: 生成提示词
  POST /api/prompt/generate
  {
    "description": "用户一句话描述",
    "style": "cartoon",  # 可选：cartoon, realistic, watercolor 等
    "age_group": "low"   # 可选：low (低年级), high (高年级)
  }
  → 返回：{"prompt_en": "...", "prompt_cn": "...", "suggestions": [...]}

  # 步骤 2: 生成图片
  POST /api/image/generate
  {
    "prompt": "用户确认的完整提示词",
    "reference_image": "base64 或 URL (可选，用于角色一致性)",
    "image_count": 4,     # 1-8 张候选图
    "size": "1080x1920",  # 竖屏尺寸
    "seed": null          # 可选，用于复现结果
  }
  → 返回：{"images": ["url1", "url2", ...], "task_id": "..."}
  ```

- **优势**：
  - **用户控制权**：用户可审核并修改 AI 生成的提示词，确保符合预期
  - **灵活性**：支持动态调整图片数量，适应不同场景需求
  - **效率提升**：从"训练 + 推理"模式转变为纯推理模式，单视频生成时间大幅缩短
  - **成本降低**：节省大量 GPU 训练算力和时间成本
  - **易集成**：标准化 API 接口，便于前端和管理后台调用

#### 3.1.2 内容处理与翻译（双版本创作）

**核心设计理念：一次输入，双版本输出**

对同一个故事内容进行两次创作适配：
- **摘要版**：精简为约 10 个分镜场景，用于漫画视频生成
- **长故事版**：完整叙述版本，用于听书音频制作

- **内容库管理**：结构化故事数据库（PostgreSQL）
- **文本处理**：
  - **双版本剧本生成**：
    - **摘要版（漫画版）**：将故事自动拆分为约 10 个关键场景，每个场景包含：
      - 场景描述（用于图像生成提示词）
      - 简短台词/旁白（15-30 秒配音）
      - 画面构图建议
    - **长故事版（听书版）**：保持故事完整性，适合 5-15 分钟音频收听：
      - 完整故事情节
      - 丰富的细节描写
      - 适合朗读的段落划分
      - 情感标注（用于 TTS 情感控制）
  
  - **多语言翻译**：DeepL API / Google Translate API / 自研翻译模型
    - 语言支持：中文、英文、阿拉伯文
    - 双版本均需翻译
  
  - **内容审核**：儿童内容安全过滤系统

- **示例流程**：
  ```
  原始故事：《孔融让梨》
  ↓
  摘要版（漫画）→ 10 个分镜：
    场景 1: 孔融家中，桌上放着一盘梨
    场景 2: 兄弟们围在桌边
    场景 3: 孔融挑选最小的梨
    ...
    场景 10: 大家夸奖孔融懂事
  
  长故事版（听书）→ 完整故事：
    "东汉时期，有个孩子名叫孔融，他聪明伶俐，懂得礼让...
     （完整叙述 800-1500 字，适合 8 分钟朗读）"
  ↓
  双版本分别翻译为中/英/阿三语
  ```

#### 3.1.3 视频与音频处理
- **视频处理**：FFmpeg（图片转视频、帧率控制、转场效果）
- **语音合成（TTS）**：
  - 中文：科大讯飞 / Azure TTS / 百度语音
  - 英文：ElevenLabs / Azure TTS / Google TTS
  - 阿拉伯文：Azure TTS / Google TTS
  - 要求：支持儿童友好音色，情感表达丰富
- **音频合成**：FFmpeg + pydub（音视频同步、背景音乐混合）

#### 3.1.4 后端与服务架构
- **后端框架**：Python (FastAPI) + Celery（异步任务队列）
- **数据库**：PostgreSQL（故事库、角色库、任务记录）+ Redis（缓存）
- **存储**：对象存储（阿里云 OSS / AWS S3）存放图片、视频、音频素材
- **定时任务**：Celery Beat / APScheduler
- **消息队列**：RabbitMQ / Redis Queue

#### 3.1.5 前端与管理后台（可选）
- **框架**：Vue.js 3 / React
- **功能**：角色创建、故事管理、任务监控、数据看板

#### 3.1.6 短视频平台对接
- **国内平台**：抖音开放平台、快手开放平台
- **国际平台**：TikTok API、YouTube Shorts API
- **抽象接口层**：统一上传接口，快速适配新平台

### 3.3 核心流程

#### 3.3.1 角色创建流程
1. 用户输入角色描述（文字）
2. AI 生成 4-8 个候选角色形象
3. 用户选择并确认主角
4. 系统保存主角设定图（作为后续生成的参考图）
5. 角色入库，供后续故事使用

#### 3.3.2 视频生成流程（双版本输出）

1. 选择故事内容（按年龄段筛选）
2. 选择已创建的角色
3. 选择目标语言（中/英/阿）
4. **系统自动进行双版本创作**：
   - **摘要版**：拆分故事为 10 个分镜场景
   - **长故事版**：生成完整叙述文本（5-15 分钟朗读版）
5. **漫画视频生成线**：
   - 以角色设定图为参考，并行生成 10 帧漫画图片（Flux.1-dev 保持角色一致性）
   - 生成摘要版配音音频（每帧 15-30 秒）
   - 图片序列 + 配音 + 背景音乐 → 合成漫画视频（约 3-5 分钟）
6. **听书音频生成线**：
   - 生成长故事版配音音频（5-15 分钟）
   - 添加背景音乐和音效
   - 合成听书音频文件
7. 自动上传至指定短视频平台（漫画视频）
8. 自动上传至音频平台/播客（听书音频，可选）
9. 记录发布结果，通知用户

## 4. 开发计划

### 4.1 时间估算说明（AI 加速版）

**为什么可以从 10 周压缩到 2-3 周？**

当前 AI 编码工具（Cursor、Copilot、Devin 等）确实能大幅加速开发，但需区分**纯编码任务**和**系统集成任务**：

| 任务类型 | AI 加速效果 | 本项目占比 |
|---------|------------|-----------|
| 单点代码生成（CRUD、脚本） | ⚡️ 10-50 倍提速 | 40% |
| API 对接（有完善文档） | ⚡️ 5-10 倍提速 | 30% |
| **Flux.1-dev 角色一致性调试** | ⚡️ **3-5 倍提速**（无需训练） | 20% |
| 内容审核/多语言校验 | ⚠️ 需人工参与 | 10% |

**优化后周期评估：**
- **MVP 版本（单语言 + 单平台）**：**2 周**（10 个工作日）
  - 使用 **Flux.1-dev 参考图驱动**实现角色一致性（无需 LoRA 训练）
  - 仅对接抖音平台
  - 故事库预置 20 个精选故事
- **完整版本（3 语言 + 多平台）**：**3 周**
  - Flux.1-dev 多道具/场景扩展支持
  - 多平台适配（抖音/快手/TikTok）
  - 多语言翻译与配音校验

> **关键前提**：团队需熟悉 AI 工具链，且有现成云资源（GPU 实例、对象存储）；**Flux.1-dev 的单图参考能力是缩短周期的关键因素**。

## 5. 风险管理

| 风险 | 影响程度 | 应对措施 |
|------|----------|----------|
| 图像生成质量不稳定 | 高 | 建立质量评估机制，支持人工审核环节；多模型备选方案 |
| **Flux.1-dev 参考图一致性偏差** | 中 | **调整参考图权重参数；优化提示词工程；建立多轮生成筛选机制** |
| **双版本内容同步问题** | 中 | **建立版本关联机制；确保摘要版与长故事版情节一致；自动化校验流程** |
| 多语言翻译准确性不足 | 中 | 使用专业翻译 API+ 人工校对；建立术语库；针对儿童内容优化翻译策略 |
| 短视频平台 API 变更 | 中 | 抽象平台接口层；密切关注官方文档更新；快速适配新接口 |
| 配音情感表达不足 | 中 | 选择高质量 TTS 服务；支持情感参数调节；针对儿童内容优化音色配置 |
| 生成速度过慢 | 中 | 优化并发处理；使用 GPU 加速；引入任务优先级队列；图片生成并行化 |
| 版权合规风险 | 高 | 确保故事内容为原创或公有领域；建立版权审核机制；避免使用受版权保护的 IP |
| 儿童内容安全风险 | 高 | 建立多层内容审核机制；符合各国儿童内容保护法规；设置敏感词过滤 |
| 文化差异与本地化 | 中 | 针对不同语言版本进行文化适配；邀请本地专家审核；避免文化冲突内容 |
| GPU 资源成本过高 | 中 | **Flux.1-dev 推理优化**；使用混合云策略；任务调度优化；考虑模型量化压缩 |
| **听书音频时长控制** | 低 | **智能文本长度预测；TTS 语速调节；分段处理机制** |
